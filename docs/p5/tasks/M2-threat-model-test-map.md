# M2 Unix-socket IPC threat-to-test map (spike entry criteria)

Scope: Linux local Unix-domain socket between the device agent and the presentation renderer. The renderer displays state and sends user-control requests; it does not receive authority to execute tools, grant permissions, or mutate canonical state. Socket IPC is a local transport, not an authentication substitute for policy checks.

**Status:** M2 spike in progress on `feat/p5-m2-ipc-spike`. Development baseline: the repository's pinned Ubuntu 24.04 CI runner and Rust 1.99.1; this does not claim a supported desktop distribution/profile. `crates/lia-device-agent/src/ipc.rs` currently implements bounded 4-byte big-endian framing, strict JSON envelope/method/UUID validation, duplicate-key rejection, strict typed user-event bodies, deadline validation, private endpoint creation/cleanup, Linux `SO_PEERCRED`, a hello → ready connection state machine, and a UID/PID-bound listener helper that negotiates framed hello/ready under one absolute monotonic deadline. The caller must supply the supervisor's expected UID and PID; the hello response issues a session UUID and echoes optional request/correlation IDs. A ready session can receive a bounded framed user event; the session, deadline and sequence are checked before the raw envelope is returned for caller policy checks, and invalid/replayed frames close the connection. Twenty-nine IPC unit tests cover malformed frames, sequence replay, expiry, phase gating, wrong-session rejection, reconnect issuing a fresh session while rejecting an old ready frame, symlink parent/endpoint rejection, inode-safe cleanup, wrong expected UID/PID rejection before frame parsing including a same-UID sibling-process test, header/body disconnect, handshake timeout shutdown, slow-drip deadline enforcement, typed event acceptance and rejection of malformed/fabricated outcome fields, and one accepted event followed by replay rejection. Local checks now cover a long-running multi-connection accept loop, ready-session snapshot delivery, a one-slot monotonic/coalescing snapshot mailbox, a bounded synchronous user-event queue that closes on full-queue backpressure without dispatch, and a supervisor that binds a launched test child PID and refreshes it after restart with a bounded restart count and monotonic backoff. The actual Godot renderer launch integration, dispatch authorization, direct separate-UID SO_PEERCRED testing across a reachable socket, stress/high-water resource measurements and full IPC-01 remain open. Namespace evidence covers refusal to traverse the owner-only socket directory as a distinct UID and rejection of a foreign-owned directory; deterministic parent-directory and endpoint-symlink swap tests verify pinned-FD cleanup and no-follow permission changes. A 50,000-case deterministic mutation-fuzz smoke passed; coverage-guided fuzzing remains open; a local UnixStream framing baseline is retained in [benchmark evidence](../../../evidence/IPC-01/2026-11-16-m2-local-socket-benchmark/README.md). See [partial local evidence](../../../evidence/IPC-01/2026-11-16-m2-parser-edge-cases/README.md) and [prior M2 checks](../../../evidence/IPC-01/2026-11-15-m2-spike/README.md).

The initial development baseline uses Ubuntu 24.04 because that is the repository CI runner; this does not select a desktop distribution or claim support. The 262,144-byte maximum and protocol version 1 come from the draft P4 IPC contract. Socket parent policy is exactly 0700 owner-only; socket mode is 0600. Socket creation pins the validated parent directory FD, binds/unlinks through `/proc/self/fd`, applies mode with `fchmodat2(AT_SYMLINK_NOFOLLOW)`, and rejects a parent replacement detected during setup; deterministic parent and endpoint swap tests verify cleanup and prevent following a raced symlink. The accept loop can use `RendererSupervisor` to bind UID/PID to its launched child and refresh the PID with bounded restart/backoff; wiring this to the eventual Godot process remains open. P4 package revision 0.3.1 defines the hello → ready phase transition and a strict user-event body: a control ID, one of four typed event names and optional bounded text only for text submission. A matching non-expired ready report is required before user events; those events carry a canonical decimal `session_sequence` beginning at zero and strictly increasing per live connection. Expired hello/ready reports do not activate the connection; expired user events do not consume sequence. Reconnect discards the old session ID and watermark. These checks reject stale/reordered frames but do not authorize controls; state-changing dispatch remains disabled pending renderer binding and policy checks. In the current spike, typed unknown-field-rejecting body validation is implemented for `presentation.user_event`; the hello/ready request bodies remain generic objects and need explicit versioned schemas before full IPC-01. Outgoing snapshots receive envelope/session checks, but their body schema and state-field mapping also need a versioned P4 contract definition. Preserve test traces and hashes as IPC-01 evidence; all gates remain Not Run until the complete matrix is executed against the implementation.
