# M2 Unix-socket IPC threat-to-test map (spike entry criteria)

Scope: Linux local Unix-domain socket between the device agent and the presentation renderer. The renderer displays state and sends user-control requests; it does not receive authority to execute tools, grant permissions, or mutate canonical state. Socket IPC is a local transport, not an authentication substitute for policy checks.

**Status:** M2 spike in progress on `feat/p5-m2-ipc-spike`. Development baseline: the repository's pinned Ubuntu 24.04 CI runner and Rust 1.99.1; this does not claim a supported desktop distribution/profile. `crates/lia-device-agent/src/ipc.rs` currently implements bounded 4-byte big-endian framing, strict JSON envelope/method/UUID validation, duplicate-key rejection, strict typed user-event bodies, deadline validation, private endpoint creation/cleanup, Linux `SO_PEERCRED`, a hello → ready connection state machine, and a UID/PID-bound listener helper that negotiates framed hello/ready under one absolute monotonic deadline. The caller must supply the supervisor's expected UID and PID; the hello response issues a session UUID and echoes optional request/correlation IDs. A ready session can receive a bounded framed user event; the session, deadline and sequence are checked before the raw envelope is returned for caller policy checks, and invalid/replayed frames close the connection. Twenty-one IPC unit tests cover malformed frames, sequence replay, expiry, phase gating, wrong-session rejection, reconnect issuing a fresh session while rejecting an old ready frame, symlink parent/endpoint rejection, inode-safe cleanup, wrong expected UID/PID rejection before frame parsing including a same-UID sibling-process test, header/body disconnect, handshake timeout shutdown, slow-drip deadline enforcement, typed event acceptance and rejection of malformed/fabricated outcome fields, and one accepted event followed by replay rejection. The full accept loop/service, actual renderer supervisor/process binding, snapshot/state delivery, dispatch authorization, backpressure, and IPC-01 remain open. See [partial local evidence](../../../evidence/IPC-01/2026-11-16-m2-parser-edge-cases/README.md) and [prior M2 checks](../../../evidence/IPC-01/2026-11-15-m2-spike/README.md).

| Threat / assumption | Required control | Test and evidence |
| --- | --- | --- |
| Attacker pre-creates or swaps the socket path | Private runtime directory; reject symlink/non-socket; create with restrictive mode; safe cleanup tied to inode | **Partial unit coverage:** non-private parent, symlink parent, pre-existing regular file and symlink endpoint are rejected; mode 0600 and cleanup preserving a replacement inode are checked. Foreign owner and concurrent path race remain open |
| Other local user or same-UID process connects | Check `SO_PEERCRED` UID and PID against values supplied by the renderer supervisor; never trust claimed identity in payload | **Partial unit coverage:** mismatched expected UID/PID are rejected before an invalid frame is parsed; a same-UID sibling process is rejected against the expected PID. Separate-UID process test, renderer-supervisor integration and forged JSON identity case remain open |
| Same-user process impersonates renderer | Peer UID/PID checks depend on a trusted supervisor; bind accepted PID to the renderer instance and authorize every control | **Partial primitive coverage:** a sibling process under the same UID is rejected when its PID differs from the expected PID. No renderer supervisor supplies/binds the PID yet. Authorization dispatch tests remain open; current code has no state-changing handler |
| Frame is malformed, oversized, truncated or has trailing bytes | Length-prefixed bounded frames; strict JSON/schema; one complete frame per message | **Partial unit coverage:** zero/oversized, truncated header/body, invalid UTF-8/JSON, trailing JSON, duplicate keys, unknown fields, invalid method/version/kind, uint64 sequence overflow, malformed user-event schemas and oversized text are rejected. Fuzz/resource-bound procedures remain open |
| Client disconnects during a write or reply | Per-connection state is disposable; canonical operation outcome remains in the store | **Partial unit coverage:** disconnect mid-header and mid-body returns EOF; handshake timeout shuts down the connection. Disconnect during reply, renderer restart and query-current-state behavior remain open |
| Renderer restarts or sends stale state/control sequence | Session-bound monotonically increasing sequence for IPC controls; stale snapshot revision cannot overwrite newer state | **Partial unit coverage:** first zero, forward increase, duplicate/backward, and cross-session user-event frames are rejected. A socket-pair listener test verifies a reconnect issues a fresh session and rejects an old ready frame. Actual renderer process restart, state revision and service-generation integration remain open |
| Slow reader or message flood exhausts resources | Backpressure, bounded queues, read/write deadlines, per-peer quotas | **Partial unit coverage:** a slow-drip hello cannot extend one absolute monotonic handshake deadline. Slow-reader write, message flood, queue cap, bounded RSS/FDs and healthy-client responsiveness remain open |
| Network exposure accidentally appears | Bind only `AF_UNIX`; no TCP listener or remote fallback | Inspect open/listening sockets and configuration; assert no TCP listener in test process |
| Renderer message attempts to claim operation success | Agent emits outcome; renderer may request controls only from explicit allowlist | **Partial parser coverage:** user-event `outcome`/unknown fields are rejected. Snapshot-derived UI and authorization dispatch are not implemented; test those in IPC-01/GODOT-01 |

The initial development baseline uses Ubuntu 24.04 because that is the repository CI runner; this does not select a desktop distribution or claim support. The 262,144-byte maximum and protocol version 1 come from the draft P4 IPC contract. Socket parent policy is exactly 0700 owner-only; socket mode is 0600. The accept API requires expected UID/PID, but the caller must bind those to the launched renderer; that supervisor is not implemented. P4 package revision 0.3.1 defines the hello → ready phase transition and a strict user-event body: a control ID, one of four typed event names and optional bounded text only for text submission. A matching non-expired ready report is required before user events; those events carry a canonical decimal `session_sequence` beginning at zero and strictly increasing per live connection. Expired hello/ready reports do not activate the connection; expired user events do not consume sequence. Reconnect discards the old session ID and watermark. These checks reject stale/reordered frames but do not authorize controls; state-changing dispatch remains disabled pending renderer binding and policy checks. Preserve test traces and hashes as IPC-01 evidence; all gates remain Not Run until the complete matrix is executed against the implementation.
